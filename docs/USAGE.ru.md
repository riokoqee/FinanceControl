# Руководство BeliLog (ベリログ)

## Version 2.11 (English)

**Profile → Data** shows estimated site storage when the browser supports it. This includes offline files. After a full restore, reset or demo, **Restore data from before replacement** can restore the previous valid state when its best-effort snapshot is available. Only one snapshot is kept; it remains local and is not part of PDF/JSON exports.

**Profile → App → Update now** saves the profile draft and reloads the app, closing open forms and dialogs. Correct an invalid profile before retrying. Automatic-rate storage failures show a separate message and retain previous rates.

## Сайт в интернете

Публичный адрес: **https://riokoqee.github.io/belilog/**. Можно открывать с телефона и компьютера или установить как приложение.

GitHub Actions в `.github/workflows/pages.yml` после каждого коммита в `main` запускает тесты, собирает сайт и публикует `dist/` в GitHub Pages. Ручной запуск доступен в Actions → Deploy BeliLog to GitHub Pages → Run workflow.

Для сборки под адрес Pages задаётся `GITHUB_PAGES=true`, поэтому Vite использует `/belilog/`; обычный локальный запуск остаётся на `/`. Иконки и шрифты учитывают этот путь.

Данные хранятся отдельно в браузере каждого посетителя. Старые записи с `localhost` не появляются на новом адресе автоматически: скачайте полную PDF- или JSON-копию в локальной версии и импортируйте её в профиле опубликованного сайта. Для переноса между устройствами также используйте полную копию.

Переезд с пути `/FinanceControl/` на `/belilog/` сохраняет то же хранилище домена `riokoqee.github.io`: ключ данных не меняется.

## Установка и работа без интернета

В профиле блок **«Приложение»** показывает состояние подготовки. При первом открытии с интернетом BeliLog сохраняет файлы всех страниц, редакторов, изображений и локальных шрифтов, включая модуль PDF. Дождитесь **«Готово офлайн»** перед отключением сети: неполная загрузка не считается готовым приложением.

В поддерживаемом браузере нажмите **«Установить BeliLog»** в профиле или выберите установку приложения в меню браузера. На iPhone/iPad откройте сайт в Safari и выберите **«Поделиться → На экран „Домой“»**. Доступность установки зависит от браузера; обычная вкладка продолжает работать.

После подготовки без сети доступны обзор, трекер, покупки, профиль и экспорт PDF/JSON/CSV. Курсы не загружаются без сети: используются последние сохранённые значения. PWA не создаёт аккаунт, синхронизацию или резервную копию данных. В установленном приложении браузер может использовать отдельное хранилище; при необходимости перенесите данные полной копией.

В профиле можно проверить обновления. Новая версия ожидает закрытия всех вкладок и окон BeliLog; после повторного открытия применяется обновление. Автоматической перезагрузки во время редактирования нет. Подготовка офлайн не защищает от очистки или удаления данных браузером: регулярно скачивайте полную копию, особенно перед очисткой хранилища.

## Возможности

- Обзор за месяц: общая сумма, сравнение с прошлым месяцем, средние расходы в день, бюджет, график и категории.
- **Лимиты категорий:** кнопка «Лимиты» на обзоре позволяет задать месячные суммы для еды, транспорта и остальных категорий. У каждого лимита своя валюта USD/EUR/KZT; смена валюты профиля его не меняет. Прогресс считается по выбранному месяцу, включая категории без трат. От 80% появляется предупреждение, при превышении — сумма перерасхода. Пустое поле или 0 убирает лимит. Эти лимиты действуют для всех месяцев и не изменяют общий бюджет.
- Трекер: добавление, редактирование, удаление с отменой, заметки, поиск (включая покупки внутри записи), фильтры по категории/валюте, сортировка и страницы по 50 записей.
- **Список покупок:** во вкладке «Покупки» заранее добавьте продукты без цены. После покупки впишите цену рядом: она сохраняется через 600 мс после ввода, при выходе из поля или по Enter. Поддерживаются запятая, точка и USD/EUR/KZT. Первая цена создаёт один расход в категории «Еда и продукты»; последующие правки обновляют его, сохраняя дату покупки и создания. Есть фильтры запланированных/купленных товаров и отдельные итоги по валютам. Удаление строки сохраняет расход; удаление связанного расхода возвращает продукт в планы. Неоплаченные планы не влияют на бюджет и стрик. Кнопка **«Подтвердить покупку»** сохраняет введённую цену и убирает товар из списка. Расход остаётся в журнале; если цена уже сохранилась автоматически, используется та же запись без дубля, с прежними датами и детализацией. При ошибке сохранения товар и черновик остаются на месте. Список сохраняется при закрытии сайта и входит в полную PDF-копию.
- Детали записи: нажмите на название расхода, чтобы добавить конкретные покупки и их стоимость. У покупок общая валюта родительской записи. Сумма позиций не может превышать общую сумму; остаток можно расшифровать позднее. Добавление, изменение и удаление позиций сохраняются сразу.
- **Шаблоны покупок:** кнопка «Шаблоны» в покупках сохраняет названия и валюты всех запланированных товаров, включая ещё не раскрытые строки. Цены и купленные товары в шаблон не попадают. Повторное применение добавляет отсутствующие планы без дублей по названию и валюте; купленный товар можно запланировать заново. Шаблоны не создают расходы и не влияют на стрик. Доступно до 20 шаблонов по 1–200 товаров; если весь шаблон не помещается в список из 1000 строк, добавление отменяется целиком.
- Профиль: имя, email, фотография, месячный бюджет, русский/английский языки, светлая/тёмная/системная темы. Имя, email и бюджет сохраняются через 350 мс после ввода, при выходе из формы, переходе в другой раздел или уходе со страницы. Тема, язык, валюта и аватар применяются сразу.
- Аватар: PNG/JPG/WebP до 8 МБ. После выбора фото открывается редактор: перемещение мышью/пальцем или стрелками, масштаб 100–400%, круглая направляющая и живой предпросмотр, сброс, сохранение 256×256 или 512×512. Можно повторно кадрировать сохранённый аватар. Отмена не меняет профиль; исходный файл не изменяется.
- Календарь активности: GitHub-подобная сетка по дням и годам. Яркость отражает число созданных записей; показываются активные дни и лучшая серия. Считается день создания записи независимо от даты покупки. Для старых записей без этой информации используется дата покупки.
- Серия учёта видна в верхнем меню, на главной и в профиле. День засчитывается новой записью расхода или кнопкой «Сегодня без трат». За каждые семь подтверждённых дней выдаётся заморозка, максимум две; она автоматически защищает пропуск без увеличения серии и награды. Лента последних дней позволяет подтвердить недавний пропуск. Подробные правила — в разделе ниже.
- При активной серии на главной и в профиле появляется постер **WANTED** с аватаром и именем: награда равна **числу подтверждённых дней текущей серии × 500 000 берри**. Замороженные дни сохраняют непрерывность без добавления берри. Берри — игровая награда, она не изменяет суммы расходов и бюджет.
- Пиратские ранги зависят от текущей серии: **1–6 дней — Новичок Гранд Лайн**, **7–29 — Восходящий пират**, **30–99 — Сверхновая**, **100+ — Легенда морей**. Прогресс до следующего ранга показан рядом с постером. Композиция WANTED сохраняется; меняются подпалины, печать и металлические акценты. Огонь и частицы сдержанные, на телефонах их меньше, при уменьшенном движении они отключены.
- После первого подтверждения дня награда плавно увеличивается и на 6 секунд появляется штамп **BOUNTY INCREASED**; переход через порог ранга сопровождается уведомлением. Перезагрузка, навигация, импорт, редактирование и дополнительные записи того же дня не повторяют эффект. Ранги вычисляются из подтверждённых дней текущей серии.
- Мягкие анимации появления, нажатий, подтверждения сохранения и изменения награды; настройка `prefers-reduced-motion` учитывается.
- Валюты USD, EUR, KZT. Ручные курсы действуют по умолчанию; в профиле можно отдельно включить автоматическое обновление Frankfurter. Оригинальные суммы остаются в исходной валюте, общие итоги приводятся к выбранной валюте.
- Демо загружается только по явному действию, текущие данные заменяются после подтверждения.

## Серии учёта

День засчитывается один раз: записью расхода или кнопкой **«Сегодня без трат»**. Каждый подтверждённый день текущей серии даёт 500 000 игровых берри; заморозка только сохраняет непрерывность. Сегодняшний день открыт до местной полуночи. Заработанное подтверждение остаётся после удаления расхода.

За каждые семь подтверждённых дней за всё время выдаётся одна автоматическая заморозка, максимум две. Излишек сверх лимита не копится, прогресс сохраняется после прерывания серии. Закрытый пропуск защищается только целиком: например, для двух дней нужны две заморозки. Если запаса недостаточно, текущая серия прерывается, лучшая сохраняется, а заморозки остаются для новой серии. Защищённые дни не добавляют дни и берри.

Лента последних дней показывает `LOGGED`, `NO_SPEND`, `FROZEN`, `MISSED` и сегодняшний `PENDING`. Дни до начала учёта имеют нейтральный статус `NONE` и не считаются пропусками. Подтверждение задним числом доступно **48 фактически прошедших часов после местного окончания выбранного дня, включая точную границу**. Если на эту дату есть реальный расход, подтверждается учёт, иначе — день без трат; фиктивный расход не создаётся. Пересчёт может вернуть потраченную заморозку и защитить другой пропуск.

Миграция сохраняет текущую и лучшую серии и награду без изменения. История может дать до двух заработанных заморозок в запас, но старые пропуски не защищаются задним числом. Местные даты не сдвигаются после смены часового пояса. Полные PDF/JSON-копии содержат историю учёта; старые форматы продолжают импортироваться, а старые вкладки не могут перезаписать неподдерживаемый формат. Подробные правила, допущения, файлы и команды тестов: [STREAKS.md](STREAKS.md).

## Экспорт и восстановление

Кнопка **«Создать PDF»** на обзоре и в трекере выгружает выбранные расходы; в деталях записи можно скачать отдельный PDF. Отчёты содержат даты, суммы, категории, заметки, состав покупок, итоги и номера страниц. Русские/английские тексты и знаки валют поддерживаются встроенным локальным шрифтом. Обычный отчёт не содержит скрытой полной копии других записей.

Кнопка **«PDF-копия со всеми данными»** в профиле создаёт читаемый отчёт за всё время и вкладывает внутрь PDF машинную резервную копию: все расходы, покупки, дату создания, аватар, язык, лимиты категорий, шаблоны, историю учёта, курсы и настройки их обновления. Это полноценный файл для восстановления, не только картинка или печатная форма.

**«JSON-копия всех данных»** сохраняет те же данные без печатного отчёта. Её можно импортировать через тот же выбор файла в профиле. **«Расходы в CSV»** выгружает таблицу для работы с расходами: ID, дата покупки, дата создания, название, категория, исходная сумма, валюта, заметка и состав покупки. Вложенные позиции находятся в одной JSON-ячейке, поэтому расход не дублируется по строкам. CSV не является полной резервной копией и не импортируется обратно.

Через **«Импортировать PDF-копию»** можно открыть такую копию и выбрать:

- **Добавить записи:** объединить расходы и список покупок, пропустив совпадающие ID, и объединить подтверждённые дни учёта; текущий профиль, курсы, режим их обновления, лимиты и шаблоны сохраняются.
- **Восстановить всё:** заменить все данные содержимым копии, включая аватар, лимиты, шаблоны, историю учёта, курсы и настройки.

Старые JSON-копии Finance Control также принимаются. Для восстановления используйте полную PDF- или JSON-копию из профиля; обычный PDF-отчёт резервной копии не содержит.

## Локальное сохранение

Все данные хранятся в `localStorage` браузера на этом устройстве. Изменения проверяются и записываются до сообщения об успешном сохранении; корректные черновики профиля и списка покупок дополнительно сохраняются при уходе со страницы. После закрытия и повторного открытия того же адреса данные восстанавливаются.

Перед изменением приложение читает актуальную сохранённую копию и объединяет независимые изменения вкладок. Устаревший редактор сохраняет только изменённые поля: новая цена или состав покупки из другой вкладки остаются на месте. Если одно поле изменено одновременно, приложение просит загрузить актуальные значения. Для списка покупок можно также явно подтвердить свои изменения. Удалённый расход не создаётся снова без такого подтверждения.

Лимиты разных категорий можно редактировать в разных вкладках. Одновременные изменения одного лимита требуют загрузить актуальные значения; сумма и валюта защищены как единое значение.

После успешной записи сохраняется дополнительная рабочая копия `finance-control:data:v1:last-good`, если хватает места. Повреждённое основное хранилище не перезаписывается при открытии: появляется панель восстановления. Можно подтвердить восстановление последней рабочей копии, импортировать PDF или начать заново. При явной замене повреждённое содержимое сначала архивируется в `finance-control:data:v1:recovery`; если архив сохранить не удалось, замена отменяется.

Старый ключ `finance-control:data:v1` сохранён намеренно: обновление и переименование в BeliLog не удаляют прежние данные. Старые записи и копии автоматически получают совместимые значения новых настроек.

При первом сохранении лимитов или шаблонов содержимое получает версию формата 2, при сохранении истории учёта — версию 3, при сохранении ручных курсов — версию 4, при сохранении настроек автоматического обновления — версию 5. Копии версий 1–4 продолжают открываться в ручном режиме. Вкладку со старой версией сайта нужно обновить: защита хранилища не позволяет затереть неподдерживаемые настройки, подтверждённые дни и курсы.

Сервер хранения данных, аккаунт и облако не используются. На другом браузере, устройстве или адресе данные автоматически не появятся — для переноса есть полная PDF/JSON-копия. Очистка данных браузера удаляет журнал. Если браузер запрещает запись или хранилище переполнено, изменение не применяется и отображается ошибка; поля редактора сохраняют черновик для повторной попытки.

## Курсы валют

В профиле откройте **«Курсы валют»**. В исходном ручном режиме укажите **«1 USD в EUR»** и **«1 USD в KZT»**, затем нажмите **«Сохранить курсы»**. USD остаётся базой со значением 1. Принимаются положительные числа от 0,000001 до 1 000 000, до шести знаков после запятой; допустимы точка и запятая.

До сохранения используются явно подписанные примерные значения: **1 USD = 0,92 EUR = 480 KZT**. В ручном режиме приложение не обращается к сервису курсов. Сохранённые вручную значения отмечаются как «Ваш курс» в интерфейсе и PDF.

При желании выберите автоматический режим **Frankfurter**. Приложение проверяет курсы раз в местный календарный день при открытии, возврате во вкладку или восстановлении сети; кнопка обновления позволяет повторить запрос вручную. Источник и даты публикации EUR/KZT видны рядом со значениями. Даты у валют могут различаться, а в выходные оставаться прежними. Это справочные курсы, а не котировки в реальном времени; описание источника — [Frankfurter](https://frankfurter.dev/).

При ошибке или без сети сохраняются последние успешно полученные значения. Данные расходов, имя и аватар сервису не отправляются: запрос содержит только пары USD/EUR/KZT. Возврат в ручной режим сохраняет текущие числовые значения и отключает последующие автоматические запросы. Поддерживаются по-прежнему три валюты.

Курсы применяются к сводкам, графику, категориям, лимитам, сортировке сумм и PDF. Исходные суммы расходов и CSV остаются в своих валютах. Обновление курса меняет пересчитанные итоги, но не переписывает расходы или бюджет. При смене валюты обзора бюджет пересчитывается; лимит бюджета общий для всех месяцев. Полные PDF/JSON-копии включают курсы, источник, даты и режим обновления.

## Дизайн

Светлая и тёмная темы используют общие смысловые цветовые переменные, шаг отступов 4/8px и радиусы 8/12/16px. Золото выделяет основные действия, навигацию, серии и награды; бирюзовый показывает успешное сохранение, янтарный предупреждает о лимите, коралловый обозначает ошибки и перерасход. Категории графика дополнительно различаются узорами и подписями сумм. Состояния бюджета сопровождаются значком и коротким текстом; ровно 100% отмечается как «Лимит использован».

Фокус клавиатуры обозначен рамкой 2px с отступом 2px. Размер мобильных элементов управления — от 44px; календарь активности прокручивается внутри своего блока. Сохранённая или системная тема определяется до первого отображения. Переход цвета занимает 180мс, а настройка уменьшенного движения отключает анимации и частицы. Постер WANTED сохраняет композицию и пергамент; ранг меняет металлические акценты, печать и подпалины.

Manrope Variable, поднабор Noto Sans JP для ベリログ и DejaVu Sans для PDF остаются локальными; уведомления шрифтов находятся в `public/fonts/`. Источники изображений и отсутствующие сведения перечислены в [ASSETS.md](ASSETS.md). Соломенная шляпа взята из `assets/`: PNG 512×512 используется в бренде, на обзоре и в постере без аватара, ICO — в иконке браузера. Графики и декор выполнены в SVG/CSS, иконки интерфейса — Lucide. Новых зависимостей и внешних шрифтов нет. Дизайн не меняет сохранённые данные, расчёты, оформление PDF и загрузку модулей по запросу. Подробности — в [аудите цветов](DESIGN_COLOR_AUDIT.md) и [отчёте о дизайне и проверках](DESIGN_REDESIGN.md).

## Производительность

Страницы, состав записи и редакторы выполняются при открытии. PDF остаётся отдельным модулем; подготовка PWA сохраняет эти файлы в фоне для дальнейшей работы без сети. В списке покупок сначала показываются 50 строк, остальные открываются кнопкой «Показать ещё»; уже введённые цены и фокус сохраняются. Сводки, поиск, сортировка, форматирование сумм и расчёт серии повторяются только при изменении соответствующих данных.

При сохранении профиль не пересоздаёт неизменённый журнал; запись по-прежнему проверяет актуальные данные и конфликты вкладок. Подробности замеров и ограничения описаны в [отчёте](PERFORMANCE.md).

Микрозамер хранилища на 500, 5000 и 50 000 записях запускается отдельно и не входит в обычные тесты:

```bash
npx vitest bench src/lib/storage/storage.bench.ts --run
```
